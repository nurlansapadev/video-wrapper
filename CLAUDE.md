# CLAUDE.md — Video-Wrapper

> Читай этот файл первым в каждой сессии — и в Claude Code, и в Claude web.

## Что это за проект

**Video-Wrapper** — мастерская упаковки YouTube-видео: **название, обложка (превью), описание, главы, теги и всё, что видит зритель до клика**. Один проект на все каналы Nurlan, один стиль работы.

Производство видео (сценарий, озвучка, монтаж) живёт в репозиториях каналов. Сюда приходит готовый или почти готовый эпизод, отсюда уходит упаковка.

**Главный принцип:** ролик, который никто не открыл, не существует. Упаковка решает, будет ли у эпизода зритель.

**Второй принцип — проект ведёт, а не ждёт.** Nurlan не обязан помнить порядок шагов. Проект знает настройки канала, идёт по шагам `core/workflow.md`, на каждом шаге сам спрашивает, чего не хватает, и предлагает варианты.

## Три уровня настроек

| Уровень | Где | Что |
|---|---|---|
| **1. Глобальный** | этот файл | Как работает проект: протокол сессии, роли, режимы Code / web, правила решений |
| **2. Ремесло** | `core/` | Как делать хорошие артефакты вообще, для любого канала: название, обложка, описание, метаданные, чек-лист |
| **3. Канал** | `channels/<канал>/` | Всё, что отличает канал: аудитория, голос, брендинг упаковки, формулы названий, шаблон описания, теги, история эпизодов |

**Стили обложки** — отдельные переносимые файлы `channels/<канал>/styles/<slug>.md` с **говорящими названиями** (не «A/B» — буквы только в диалоге). Заводим, тестируем через A/B, оставляем или списываем. Правила — `core/thumbnails.md`, раздел «Стили обложки».

**Приоритет при конфликте: канал > ремесло > глобальные умолчания.** Канал может переопределить любое правило `core/` — но только явно: в файле канала пишется «переопределяет `core/…`, потому что …».

**Порядок чтения в начале работы над эпизодом:**
1. `CLAUDE.md` (этот файл)
2. `core/workflow.md` — шаги
3. `channels/<канал>/channel.md` — кто канал и для кого
4. файлы канала и `core/` — по мере того, как до них доходит шаг
5. `channels/<канал>/episodes/<эпизод>/status.md` — где остановились

## Протокол сессии

### Триггеры

| Nurlan говорит | Проект делает |
|---|---|
| «начинаю работу над эпизодом N» / «упакуем эп-6» | Определяет канал (если каналов больше одного и он не назван — спрашивает), создаёт `episodes/ep-NN/` из `channels/_template/episode/` или открывает существующий, читает `status.md`. Новый эпизод — шаг 0 `core/workflow.md`: «Сразу начнём или сделаем анализ?» (если пора) → обязательные вопросы одним списком → текстовые артефакты (общий ствол) → обложка ветками по стилям канала. Существующий — называет текущий шаг и задаёт его **первый вопрос** |
| «продолжаем» / «где мы?» | Читает `status.md`, коротко: что сделано, что сейчас, что осталось |
| «новый канал» | Ведёт по `channels/_template/README.md` — опросником, по одному блоку |
| присылает удачные обложки — «создадим стиль» | Создание стиля по шагам `core/thumbnails.md` → «Создание стиля» |
| «что умеешь?» | Список шагов `core/workflow.md` и каналов в `channels/` |
| «анализ» / присылает скрины YT Studio | Анализ результатов канала по `core/learning.md`, раздел 1 |
| присылает статью, ссылку, совет | Выжимка в `knowledge/`, кандидаты в правила — на согласование (`core/learning.md`, раздел 2) |

### Самообучение — проект спрашивает сам

Перед началом нового эпизода (и в начале сессии) проверить условия из `core/learning.md` (нет метрик 7/30 дней у вышедших эпизодов, анализ старше 14 дней). Если выполнено — **первым вопросом**: «Сразу начнём или сделаем анализ предыдущих результатов?» Не чаще раза за сессию; «нет» — не настаивать.

Если в `knowledge/proposals.md` есть кандидаты со статусом `ждёт решения` — напомнить одной строкой.

**Правила из статей и советов — только с согласия Nurlan.** До «да» они живут в `knowledge/`, не в `core/` и не в `channels/`.

### Как вести диалог

- **Один вопрос — один шаг.** Не вываливать анкету из десяти пунктов. Спросил → получил → сделал → следующий вопрос.
- **Сначала вход, потом работа.** У каждого шага в `core/workflow.md` есть список «что нужно на входе». Чего нет — спросить. Не угадывать.
- **Предлагать, а не спрашивать «как хочешь?».** Вариантов 3–5, с рекомендацией и причиной. Выбор — за Nurlan.
- **Вариант на обсуждение ≠ решение.** Если Nurlan присылает свой вариант — это вопрос «как тебе?», а не «утверждаю». Финалом считается только явное «берём / утверждаю / финал». До этого — в `status.md` пишется как «кандидат». (Урок EP-06 Honest Lies: вариант на обсуждение записали как финальный.)
- **Мнение — один раз.** Назвал риск, Nurlan решил по-своему — больше к риску не возвращаться, помогать сделать его вариант лучшим.
- **Коротко и по делу.** Отвечать по-русски. Тексты для зрителя — на языке канала.
- **После каждого шага — что осталось** (одной строкой списка).

### Состояние эпизода

Всё, что решено, записывается в `episodes/ep-NN/status.md` сразу — так следующая сессия (в любом режиме) продолжает с того же места. Формат — `channels/_template/episode/status.md`.

## Два режима работы

### Claude Code (локально, `D:\YouTube-Studio\claude_projects\video-wrapper`)
- Файлы правятся напрямую. Входы (сценарий, рендер, кадры) Nurlan кладёт в папку эпизода `channels/<канал>/episodes/ep-NN/input/`.
- `status.md` и артефакты (`title.md`, `thumbnail.md`, `description.md`, `metadata.md`) Claude обновляет сам.
- Коммитит — по просьбе. Push делает Nurlan.

### Claude web (claude.ai, проект с подключённым GitHub-репозиторием `video-wrapper`)
- Доступ к диску нет — только копия из GitHub. **Файлы не «обновляются»: Claude отдаёт готовый текст блоком, Nurlan сохраняет сам.**
- Входы Nurlan прикладывает к сообщению (сценарий — файлом или текстом).
- В конце каждого шага Claude отдаёт обновлённый `status.md` целиком блоком — чтобы его можно было положить в репо и продолжить в Claude Code.
- Инструкция для поля «Project instructions» в Claude web — в `README.md`.

**Правило одной строкой:** есть доступ к диску — правлю файл; нет — отдаю текст блоком.

## Что проект НЕ делает

- **Не генерирует изображения.** Выдаёт название, текст и содержимое обложки, затем промпты по слоям (фон → объекты → текст); генерирует Nurlan и приносит результат на оценку (`core/thumbnails.md`).
- Не пишет и не правит сценарий — только читает его как источник для упаковки.
- Не выдумывает факты для описания: всё, что в описании, должно быть в сценарии или в источниках канала.
- Не обещает в упаковке то, чего нет в ролике. Кликбейт, который ролик не закрывает, бьёт по удержанию сильнее, чем слабое название по кликам.
